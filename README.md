# رادار كشف عروض وتخفيضات مصر الشامل (Egypt Deals Radar & Multi-Store Scraper)

[![Scrape Amazon Egypt Tez Catalog](https://github.com/millstyxamr-droid/amazon-deals-radar/actions/workflows/scrape.yml/badge.svg)](https://github.com/millstyxamr-droid/amazon-deals-radar/actions/workflows/scrape.yml)

مشروع متكامل ومتقدم لكشط بيانات عروض وتخفيضات **أمازون مصر بالكامل (Amazon Egypt)** و **جوميا مصر (Jumia Egypt)** مع **بنية متعددة المتاجر (Multi-Store Architecture)** ومحرك ذكي لكشف العروض الحقيقية، مقارنة الأسعار بين المتاجر لرصد المتجر الأرخص، وتتبع تاريخ الأسعار واستبعاد التخفيضات الوهمية.

---

## 🛒 تغطية المتاجر المدعومة (Supported Stores)
1. **أمازون مصر بالكامل (Amazon Egypt):**
   * عروض وتخفيضات اليوم (`/deals`).
   * الموبايلات والتابلت (`amazon-mobiles`).
   * اللابتوبات والكمبيوتر (`amazon-computers`).
   * الإلكترونيات والتلفزيونات (`amazon-electronics`).
   * الأجهزة المنزلية الكبيرة والصغيرة (`amazon-appliances`).
   * مستلزمات المنزل والمطبخ (`amazon-kitchen`).
   * الأزياء والملابس رجالي وحريمي (`amazon-fashion-men` / `amazon-fashion-women`).
   * الجمال والعطور ومستلزمات الأطفال (`amazon-beauty` / `amazon-baby`).
   * سوبر ماركت وبقالة أمازون تيز (`amazon-supermarket` و 110 قسم Tez).
2. **جوميا مصر (Jumia Egypt):**
   * عروض الفلاش اليومية (`jumia-flash-sales`).
   * الموبايلات والتابلت (`jumia-phones-tablets`).
   * التلفزيونات والإلكترونيات (`jumia-electronics`).
   * الأجهزة المنزلية والسوبرماركت والأزياء.

---

## 💻 أوامر التشغيل السريعة (CLI Commands)
* `npm run scrape:full`: كشط كامل الأقسام لجميع المتاجر.
* `npm run scrape:amazon`: كشط أقسام أمازون مصر فقط.
* `npm run scrape:jumia`: كشط أقسام وعروض جوميا مصر فقط.
* `npm run scrape:deals`: كشط عروض اليوم الكبرى من أمازون مصر.
* `npm run build:site`: بناء وتحديث لوحة التحكم والموقع الثابت `dist/index.html`.
* `npm test`: تشغيل كامل حزمة الاختبارات (106 اختبار آلي).

## ⚡ التشغيل الآلي والجدولة عبر GitHub Actions

يحتوي المشروع على workflow متكامل في المسار:
[`.github/workflows/scrape.yml`](file:///.github/workflows/scrape.yml)

### 1. توقيت الجدولة التلقائية (Schedule Cron)
* **الكرون المستخدم:** `"0 */6 * * *"`
* **التوقيت:** يعمل كل 6 ساعات بتوقيت جرينتش (UTC) عند الأوقات: `00:00`, `06:00`, `12:00`, `18:00` UTC.
* **بتوقيت القاهرة (مصر):**
  * التوقيت الشتوي (UTC+2): `02:00`, `08:00`, `14:00`, `20:00`.
  * التوقيت الصيفي (UTC+3): `03:00`, `09:00`, `15:00`, `21:00`.
* **ملاحظة مهمة حول دقة التوقيت:** مجدول GitHub Actions يعمل بنظام best-effort queue مجاني، لذا قد يتأخر بدء التشغيل التلقائي بمقدار **5 إلى 15 دقيقة** أحياناً بحسب ضغط سيرفرات GitHub في أوقات الذروة.

---

### 2. إدارة قاعدة البيانات وحفظ التاريخ بين الـ Runs (Database Persistence)
ملف قاعدة بيانات SQLite الثنائي `data/catalog.db` **لا يتم عمل commit له على فرع main** نهائياً لتفادي تضخم مستودع Git وتشوه سجل الفروقات (binary diffs). تم إضافته وقواعده إلى [`.gitignore`](file:///.gitignore).

يتم حفظ واستعادة التاريخ السعري بين الجولات عبر 3 طبقات حماية:

1. **GitHub Actions Cache (الطبقة الأساسية السريعة):**
   * يتم استرجاع `data/catalog.db` باستخدام مفتاح الكاش `catalog-db-${{ github.run_id }}` مع مفتاح الاستعادة البادئ `catalog-db-` لجلب آخر نسخة ناجحة فوراً.
   * عند انتهاء الجولة بنجاح يتم عمل `PRAGMA wal_checkpoint(TRUNCATE)` لدمج تغييرات الـ WAL وحفظ الكاش الجديد.

2. **Gzip Snapshot Artifact (الطبقة الاحتياطية المجانية):**
   * يتم ضغط قاعدة البيانات إلى `data/catalog.db.gz` ورفعها كـ Artifact باسم `catalog-db-snapshot` بصلاحية حفظ **14 يوماً**.
   * إذا لم يجد السيرفر كاش نشطاً، يقوم تلقائياً عبر GitHub CLI (`gh run download`) بتحميل آخر snapshot artifact وفك ضغطه واستئناف العمل منه.

3. **سحابة Cloudflare R2 / AWS S3 (اختياري بمفاتيح الأمان):**
   * إذا تم تعريف أسرار `R2_BUCKET_NAME` و `AWS_ACCESS_KEY_ID` و `AWS_SECRET_ACCESS_KEY`، يقوم الـ workflow تلقائياً برفع وتنزيل نسخة مضغوطة من وإلى السحابة لضمان حفظ البيانات لسنوات دون التقيد بمهلة الـ 14 يوماً.

4. **ماذا يحدث لو انتهت مدة الـ Artifact أو فُقد الكاش (Fallback Strategy):**
   * إذا تم تشغيل المستودع بعد انقطاع طويل (أكثر من 14 يوماً دون تشغيل)، يقوم السكربت بعمل **Fresh Run Fallback** تلقائياً:
   * يقوم `src/db.js` بإنشاء قاعدة بيانات جديدة فارغة وتطبيق كامل الـ schema، ثم يزحف الأقسام ويبني السجل السعري الجديد بالكامل دون أن يفشل الـ run.

---

### 3. التشغيل اليدوي والتحكم (`workflow_dispatch`)
يمكن تشغيل الجولة يدوياً في أي وقت من تبويب Actions في GitHub مع تمرير الخيارات:
* **`limit` (اختياري):** تحديد عدد الأقسام المراد زحفها فقط (مثلاً: `2` لاختبار الجولة في دقيقة واحدة والتأكد من أنها خضراء).
* **`resume` (اختياري - boolean):** استئناف جولة سابقة وتخطي الأقسام التي تم كشطها بنجاح خلال آخر 6 ساعات أو من آخر صفحة توقفت عندها (`last_page`).

---

### 4. الفحص الصحي ومراقبة الجودة (Healthcheck)
يقوم سكربت [`scripts/healthcheck.js`](file:///scripts/healthcheck.js) بعد انتهاء الكشط بفحص صحة الكتالوج وطباعة:
* إجمالي عدد المنتجات النشطة والمسجلة.
* عدد لقطات الأسعار (snapshots) المسجلة خلال آخر 24 ساعة.
* نسبة الأقسام التي رجعت 0 منتجات أو متعثرة.
* الأقسام التي فشلت 3 مرات متتالية.
* **شرط الفشل الحاسم:** إذا كانت `pages_ok == 0` (فشل الزاحف في جلب أي صفحة)، يخرج السكربت بكود خطأ `exit 1` مما يجعل الجولة في GitHub Actions **حمراء فوراً** لتنبيهك بوجود مشكلة حجب أو تغيير في بنية الصفحة.

## 🎯 ميزات محرك كشف العروض (Deals Radar Engine)
1. **تتبع منتج معين وقائمة المراقبة (Product Watchlist & Price/Discount Alerts):**
   * إمكانية تتبع أي منتج محدد عبر كود `ASIN` أو رابط صفحة المنتج.
   * تحديد **سعر مستهدف (Target Price بالجنيه)** أو **نسبة خصم مستهدفة (% الخصم Target Discount)**، أو كلاهما معاً.
   * التنبيه الفوري عند تحقيق أي من الهدفين أو عند هبوط السعر.
   * زر `⭐ راقب السعر` متاح مباشرة في صفحة الـ HTML على كل كرت لإضافته بنقرة واحدة وتحديد السعر أو النسبة المستهدفة.
   * ملف `watchlist.json` لحفظ المنتجات المراقبة وتاريخ تغير أسعارها.

2. **حساب نسبة الخصم الحقيقية (% OFF):**
   يقوم بمقارنة السعر المعروض الحالي بالسعر المرجعي / الأصلي قبل التخفيض بدقة:
   $$\text{Discount \%} = \frac{\text{Original Price} - \text{Current Price}}{\text{Original Price}} \times 100$$

3. **حساب التوفير المباشر بالجنيه (EGP Saved):**
   حساب كم جنيهاً ستوفره فعلياً عند شراء هذا المنتج.

4. **سجل تاريخ الأسعار (Price History Tracker):**
   قاعدة بيانات SQLite في `data/catalog.db` تحفظ تاريخ الأسعار لكل `ASIN` مع التاريخ ورقم الجولة، لتحديد أقل وأعلى سعر وصل له المنتج ورصد أي انخفاض جديد في السعر فور حدوثه.

5. **تقرير فوري عند كل عملية كشط:**
   يطبع ملخصاً بأكبر تخفيضات في المتجر، وأكبر المنتجات التي تحقق أعلى وفر مالي.

6. **لوحة تحكم تفاعلية (HTML Deals Dashboard):**
   * شارات عروض بارزة على كل كرت (`خصم 31%` | `وفر 163.55 ج.م`).
   * أزرار تصفية سريعة بنقرة واحدة (`كل العروض الحقيقية`، `خصم > 30%`، `وفر > 50 ج.م`).
   * ترتيب فوري حسب الأعلى خصماً أو الأكبر وفراً بالجنيه.

## 🛡️ سلامة البيانات (Data Integrity)

> **قاعدة صارمة:** ممنوع وجود أي تاريخ أسعار مصطنع (demo/synthetic) في قاعدة بيانات الإنتاج أو في أي ملف منشور.

- **المصادر الموثوقة فقط** هي اللي بتدخل في حساب العروض: `full_store_scraper`، `price_history.json`، وأي كشط حقيقي.
- المصدر `seed_history` (داتا تجريبية) **مرفوض تلقائياً** في `src/pricing.js` عبر `UNTRUSTED_SNAPSHOT_SOURCES`، ومش بيأثر على الخصم أو الثقة أو الترتيب.
- سكربت `scripts/seed_demo_history.js` **لا يعمل** إلا بموافقة صريحة: `--confirm-demo-data`، ومخصص للتجربة المحلية فقط.
- **تنظيف أي داتا وهمية:**
  ```bash
  npm run db:purge-seed -- --dry-run   # معاينة فقط
  npm run db:purge-seed                # حذف فعلي + مسح الكاش
  ```
  السكربت بيحذف لقطات `seed_history`، وبيصفّر `deals_scores` و`channel_queue` المعلّقة، لأنها كانت محسوبة من الداتا القديمة.
- **الاختبارات معزولة تماماً:** `test/build_pages.test.js` و`test/brand_report.test.js` بيبنوا قاعدة بيانات مؤقتة عبر `CATALOG_DB_PATH`، فمش بيعتمدوا على داتا الإنتاج ولا بيلمسوا `dist/` الحقيقي.
- **لا يُنشر أي "خصم حقيقي"** قبل مرور 7 أيام على الأقل و5 لقطات سعرية حقيقية لنفس المنتج. قبل كده الواجهة بتعرض "لسه بنجمع بيانات".

## 🔎 الكشط بالبحث (Search Crawl) — الطريق الموثوق للتغطية

> **مهم:** أرقام `nodeId` في `categories.json` جزء كبير منها مُخمَّن أو مربوط بقسم غلط (مثال: `baby-diapers` كان بيرجّع مناديل وشامبو بدل الحفاضات). عشان كده الاعتماد على أقسام الـ `nodeId` لوحده **لا يكفي** لتغطية كتالوج أمازون ناو.

الحل: كشط نتائج البحث مباشرة عبر:

```
https://www.amazon.eg/tez/browse/search?qcbrand=sAuWWBROaG&searchKeyword=<keyword>
```

### الأوامر

```bash
# كلمة بحث واحدة (لازم تحدد القسم اللي هتتسجل فيه المنتجات):
node full_store_scraper.js --search "pampers premium" --search-category baby-care

# قائمة كلمات بحث جاهزة (70 كلمة: بامبرز، حفاضات، أجبان، منظفات...):
npm run scrape:search
# أو
node full_store_scraper.js --search-file search_keywords.json

# تجربة أول كلمتين بس:
node full_store_scraper.js --search-file search_keywords.json --limit 2
```

### إضافة كلمات جديدة

عدّل `search_keywords.json` وأضف عنصر بالشكل ده:

```json
{ "keyword": "pampers premium", "category_id": "baby-care" }
```

- `keyword`: نص البحث كما تكتبه على أمازون (عربي أو إنجليزي).
- `category_id`: **إجباري**، ولازم يكون ID موجود فعلاً في `categories.json` (مثل `baby-care`, `dairy-cheese`, `laundry`).
- السبب: `saveDepartmentBatch` بيكتب `products.category_id` بالقسم الممرر، فلو مررنا قسم غير موجود أو `null` هنتسبب في تصنيف غلط.
- في وضع البحث **لا** يتم استبدال اسم/رابط القسم الحقيقي بالاسم المؤقت `Search: ...`.

> نصيحة تشغيلية: شغّل `scrape:search` بجانب `scrape:full` كل دورة. البحث بيمسك المنتجات اللي أقسام الـ `nodeId` فاتتها، وأي منتج متطابق بيتحدّث قسمه تلقائياً للقسم الصحيح.

## 🖥️ تطبيق سطح المكتب (Windows Desktop GUI — `AmazonDealsRadar.exe`)

يتضمن المشروع الآن برنامجاً تنفيذياً مستقلاً ذو واجهة رسومية حديثة باللغة العربية:
* **مسار الملف:** [`AmazonDealsRadar.exe`](file:///AmazonDealsRadar.exe) (أو داخل مجلد [`dist/AmazonDealsRadar.exe`](file:///dist/AmazonDealsRadar.exe)).
* **طريقة التشغيل:** انقر نقراً مزدوجاً على الملف مباشرة من Windows Explorer بدون الحاجة لفتح Terminal.

### مميزات الواجهة الرسومية:
1. **لوحة التحكم السريعة (Dashboard):** عرض فوري لعدد المنتجات والصفقات الحقيقية وتخفيضات الأسعار.
2. **مركز العمليات بنقرة واحدة:** تشغيل الكشط، فحص وتحديث الصفقات، نشر التليجرام (تجريبي ومباشر)، تصدير Excel، وبناء الموقع.
3. **جدول استعراض الصفقات التفاعلي:** فحص المنتجات والأسعار ونسب الخصم والوفر مع زر فتح رابط المنتج على أمازون مصر مباشرة مع كود الأفلييت.
4. **محرر الإعدادات (`config.json`):** تعديل كود الأفلييت، توكن البوت، معرف القناة، عدد الصفقات، والحد الأدنى للخصم مع حفظ وتطبيق فوري.
5. **شاشة السجل الحي (Terminal):** متابعة مخرجات أوامر Node في الوقت الفعلي مع إمكانية إيقاف أي مهمة بضغطة زر.
